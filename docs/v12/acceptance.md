# 《金沙：古蜀秘境》浏览器版验收

以下记录对应 V12 发布时的界面。现行版进入河岸或工作台后可打开「回顾章节」，操作见[游戏说明](../../README.md)。

从首页「开始探索」进入古河岸。已有记录的玩家可选「章节重玩」，直接回到归档工位。新旧存档共用同一入口，首页复勘按需加载工作台，烁羽的野外模型在进入河岸时加载。

## 一条调查主线

| 现场 | 玩家亲手完成的调查 | 如何复核 |
| --- | --- | --- |
| 滨河探方 | 刷开东西两窗，标出砂泥界线，摇筛，寻找陶器口沿。翻看器壁上缘与夹砂断面，最后配层位签 | 可返回剖面、筛盘和陶片；取样针、摇筛和两处观察均保留 |
| 古河道渡口 | 驾筏避浅滩，在两处水标靠泊，拖测线横渡河面，记录漂木往返经过测线 | 错过时可等下一趟，也可架触铃；河心回涡为自选挑战 |
| 古木鉴定台 | 环看木根，沿仍与根盘相连的侧根取样，转动参照切片配准导管，再观看秋枫生长 | 可从显微镜回到根盘，再用同一份样本继续，也可重看生长 |
| 滨岸治玉作坊 | 比较素绳、砂与水在玉面上的不同效果，往复锯切，转动切开的一半，在斜光下记录弧纹 | 角度不合时保留切口，可继续转动 |
| 陶作修复架 | 调口规，拖转三块残片，使断口逐一吻合，再转动整器检查侧缘连续性 | 可撤回刚接合的陶片；复勘会改变起始角 |
| 铜鸟支护台 | 从侧面辨认薄尾，移动两个支点，缓降铜鸟试托 | 根据尾端偏沉的方向调整后重试 |
| 滨河象牙埋藏区 | 换机位，对三处关系分别放同框比例尺、调焦并拍摄 | 可单独重拍一格，复勘时由玩家决定是否用新底片替换原图鉴 |
| 金箔光学工位 | 转看试片厚薄，推动灯位，在掠射与透射光下辨别闭孔、折痕和边缘缺口 | 可回看上一片；复勘会重排实物盲样 |
| 九柱基址 | 把测绳从一个洞心拉到另一个洞心，实测开间、进深，再用对角线复尺 | 错误配对显示实际距离；完成后沿东南轴线候日 |

遗址研究为这些调查提供线索；烁羽、调查路线、工位样本和上部建筑均含教学创作。九柱的间距可从平面测量；冬至日出是本作用来体验方位研究的情景。[考古依据和取舍](../v11/design.md)

## 归档后的玩法

古河水槽会在归档第一、三、九站时分别开放「退水河湾」「双脉浅滩」「复流古汊」。每次投放粗、中、细砂各 36 粒。闸门开度改变颗粒运动，采样窗的实收颗粒决定层性，前一层的厚度会影响下一层的落点。试流、撤层和再配支持反复实验；每份岩芯分别保存进度与最佳投料次数。[粒子计算与触屏记录](flume/checks.json)

每站收获页可以立即重玩。章节卡保留完成复勘的次数，中途退出可直接返回章节架。陶作的残片起角和金箔盲样次序会随已完成的复勘轮次变化，重新打开浏览器后仍会延续。

## 两种声音

序章、九处现场和冬至由男声讲述，初落河岸及九条途中对白由烁羽的女声讲述。台本以完整短句合成，分别设置停连、语速、专名读音和角色响度。21 个 24 kHz 单声道 PCM 文件随本机游戏提供；玩家进入相应现场时才加载。故事对白出现时配乐降低，重听和切场会让前一句快速淡出。首页「烁羽 · 羽装」可试听烁羽；现场「旁白原文」保留逐字台词与重听入口。[声音来源与双角色试听](../../public/credits-v10.html) · [模型说明](https://huggingface.co/hexgrad/Kokoro-82M-v1.1-zh)

## 浏览器操作与存档

- 从空白浏览器档案走完九站、可选回涡、冬至候日和金面具特展，期间在第三站刷新页面，并回图鉴核对三张实际拍摄的照片。[生产主线](campaign/playthrough.json)
- 从已有三站和九站的测试存档打开首页重玩，在嵌套的水槽中按返回或 Esc，回到原来的章节选择或收获页；再次归档保留原主线与经验。[重玩与解锁](replay/replay.json)
- 从四站旧档导入，核对当时可用的阅历、购买强化后的余额、装备外观、重新进入第五站及首次鉴定奖励。[存档迁移](collection/migration-checks.json)
- 前三站在桌面与 390 像素视口分别验证了刷错层、找错材料、摇筛后返回、沿根取样及显微观察。中段三站从真实首页重玩到收获页，另检查快速划动后紧接轻触、取消手势和单次点击只激活一项。[前三站的 70 项检查](fieldwork/interaction-results.json) · [工坊手势](workshops/gestures.json)
- 后三站在 390 × 844 触屏模拟中用手势完成三片盲样的双光位观察、三段测量与三张不同的原位底片。搭建了两个以上的取景关系后，可回到底片格选中其中一张重拍。[圣域触屏检查](sanctuary/touch.json)
- 故意延迟和中断烁羽模型请求，检查加载画面和同页修复，再核对首页角色档案、竖屏飞行和支线标记。[加载失败与重试](campaign/boot-retry.json) · [竖屏入口](campaign/portrait.json)
- 在正式入口试听烁羽、进入旧档第一站、打开旁白原文并重听，核对全 21 份交付音频均可解码。21 段总长约 3 分 15 秒。另以连接游戏音轨的分析器验证声音、配乐、左右方位提示、静音及取消后的输出。声音的自然度可在正式剧本和场景下试听。[正式入口的语音请求](voice/browser.json) · [独白与环境声](campaign/audio.json)

## 移动和渲染

最终生产包的九道主线均完成了现场取证和收获归档，相关独立自动化测试 288 项通过。九站现场输入阶段的帧间隔 P95 在 16.9–17.1 毫秒之间。最慢的单帧来自圣域以外的滨河探方，间隔 266.7 毫秒；象牙原位摄影也记录到一次 217 毫秒的间隔。这个数字包含屏幕读回、浏览器调度及留档截图。它反映整条交互链的等待时间，无法单凭一次记录定位所有停顿。[本机正式版主线与帧时间](campaign/playthrough.json)

沿实体边缘移动时，烁羽能贴边滑动；迎面顶住器架时可以改向、跃起或起飞。领航会为已发现地点寻找通路。验收从新档步行和闪身撞向探方筛筐，实测烁羽中心到筛筐碰撞面的最小间隔约 0.62 米，随后绕开、到西岸停栖、跨河飞至石场、在北汊潜入水下。用导航模型遍历 13 个地点之间的 156 种有向组合，逐段检查占用空间。[输入与位置记录](traversal/travel.json) · [航路检查](traversal/corridors.json)

祭祀区的土壁、沉积颗粒与金箔凹凸图经过离线烘焙。进入秋枫的显微观察时，程序可利用空闲时间预编译树冠材质。静止的水槽按需绘制；取样、改闸和拖动视角会重新驱动画面。正式主线记录了每站的帧数、中位数、P95 和最长帧。测试机为 Windows 上的 Edge、AMD Radeon 集显。进入新场景和拍摄底片仍会产生长帧，390 像素测试采用浏览器触摸仿真。[逐站帧时间](campaign/playthrough.json)
