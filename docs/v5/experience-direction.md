# V5 体验方向：让每一次发现改变旅程

2026-11-18。此文保留本轮 UI / UX 独立诊断与实施建议的初稿；后续已实现范围与验证见 [interface-delivery.md](interface-delivery.md)。初始审查使用本地 V4、1440×900，已进入游戏、行走、开启倾听及空图鉴；截图与脚本在 [experience-captures](experience-captures/) 和 [experience-audit.cjs](experience-audit.cjs)。

## 1. 现有体验的核心问题

**身体能力已经丰富，玩法回报没有跟上。** 当前主线仍是沿路移动、E 打开器物、三选一、前往下一点；水下、飞行、停栖并不通往足够独特的目标和奖励。玩家能做很多动作，却缺少值得用它们解决的问题。新增装饰和动作按钮不会单独解决这个问题。

**开场构图给出矛盾的方向信息。** 起点正前方的大圆石占据视野中轴，可通过的树根门却位于左侧；“往有光的地方”没有提供第一步可读的空间指向。应该让首个异常、流动光迹或飞鸟明确沿弯道进入根门，远处只露下一个英雄地标的局部。

**视觉信息层级偏向网页展馆。** 左上大标题、长目标正文、收集数、左下身体状态与说明、底部键位和按钮并存。Q 倾听时又把文字压到角色肩部，底部字幕再次描述相同方向。首图见 [v4-start.png](experience-captures/v4-start.png)，倾听见 [v4-hint.png](experience-captures/v4-hint.png)。

**记录没有变成行动工具。** 空图鉴的五张相同灰卡只告知“还没找到”，没有当前位置、已知方向、未解异常或发现关联。见 [v4-journal.png](experience-captures/v4-journal.png)。已收集器物主要是阅读内容，较少反过来帮助识别下一处环境。

**关卡节奏缺少差异。** 当前看见、靠近、阅读的节拍重复。应该把手眼协调、方向判断、空间观察、路线选择和安静收尾交错编排，分别给予环境、能力/路线、叙事三种反馈。

## 3. 推荐的 V5 体验主张

**“把失去联系的林河重新唤醒。”** 玩家不是沿线答完五题，而是观察异常、使用身体与光的能力作出试验，让风、水、树与日轮重新回应。文化器物是理解这片记忆的依据，虚构机关不冒称考古事实。

一个完整事件必须包含：可见的异常 → 可读操作 → 逐步反馈 → 世界变化 → 持久记录。例如三处风铃只亮一处，飞上高枝后按节奏回应，风流贯通、飘叶转向、远处光环出现，行旅图留下风印并记住最佳飞行成绩。

建议四种主线挑战与一个终章：

1. **听风 / 根门**：用Q辨认目标方向，靠近按F或E唤醒三处回声。反馈来自树根光流与路口变化，而非答题弹层。教学一次只揭示一个动作。
2. **穿风 / 高枝**：穿过有高低变化的风环、利用上升气流抵达新落点。通关不苛刻，计时与最佳成绩可重复挑战；失败回到已知落脚点，不丢失收集。
3. **归水 / 古河湾**：水下光点、短路线选择或顺序机关；氧气和安全上浮参与判断。完成后河面与岸边生态变化，得到可见反馈。
4. **引光 / 暮色庭**：转动/对齐若干空间部件，让光路接通；应能在三维空间看到当前方向与未接通之处，不把谜题装进三选一表单。
5. **日轮回声**：使用前四种经验完成短而完整的最终仪式。结局展示自己唤醒的区域、可选发现和最佳成绩，允许回去补探索。

上述具体机关由关卡主控落地时确定；我的 UI 设计不强制五件文物变成魔法机器。已完成旧存档应能进入新旅程，不破坏既有文化收集。

## 4. 信息与视觉系统

### 辨识元素：随探索显影的林河行旅图

从本地路线投影生成原创图，而非外部整张地图：当前区域画出河线、树形/岸脊剪影和已知节点；下一段仅留一小段淡线；未探索区域不展示名字、精确形状、谜题答案或全部资源点。玩家标记只在此页，不常驻小地图。

图上的每个标记含明确状态：见过、尚未解开、已唤醒、可重试。当前目标可追踪；追踪只驱动Q风向提示，不传送。完成标记打开对应记录，未见标记不暴露详情。远方有回响可以被记录为文字线索而非精确坐标。

**配色**：夜林 `#112b2b`，地图旧纸 `#dfd1ae`，墨绿 `#3e554c`，阳光金 `#c7a85e`，陶土铜 `#b9754f`，河光 `#78a6a3`，暮色 `#65556e`。旧纸只用于地图/记事这种有真实语义的面，不把整个游戏改为奶油营销页。区域色引导可读性，不使用彩色 UI 补偿世界单调。

**字级**：本地宋体负责章节/笔记，清楚的黑体负责状态、距离和操作；游戏常驻正文至少12px，窄屏不把关键动作缩成8px。长考据放在资料层，行动层直接写“转动”“回应”“潜入”“重新挑战”。

**布局**：

```text
地区 · 当前目标                    声音 / 设置
一行具体行动                         
可选进度：印记、已发现微光            
                  [三维世界目标]
                 E 转动水闸          
                                     
身体状态/羽力          行旅图 M · 手册 J · 留影 P
                对白字幕
```

主HUD的最重要信息是“这里发生什么”和“眼下可做什么”。挑战中，用小型专属条替代普通目标：飞行显示通过数/时间；共鸣显示已回应节点；光路显示相连段数。隐藏与当前情境无关的控制说明。

**发现动效有因果**：首次看见时点到为止；进度一步完成时对应刻痕亮起；真正完成时环境先变化，然后0.8–1.5秒的印记落入行旅图。不能每捡一个小物就遮盖大半屏幕。减少动态设置保留所有数值、颜色与文本反馈。

### 记录与奖励分层

- 四枚主线回声印：对应真正改变世界的事件，驱动结局。
- 可选微光/手记：奖励偏离主路、停栖观察、潜水探索，地图只显示已见线索。
- 飞行最佳成绩：给已经会玩的玩家重复目标，不阻塞想安静探索的玩家。
- 五件文化器物：保留真实模型、考据来源与观察问答，单独归档，不能和主线进度混淆。

## 5. 可实施接口与验收

建议 UI 模块独立于Three.js：`createExperienceUI({onMap,onTrack,onRetry,onClose})`，以 `update(snapshot)` 渲染，不在DOM中计算游戏规则。字段建议包含 `mode, chapter, objective, completedSeals, discoveredRegions, discoveries, challenge, trackable, currentPosition, route`。主控持有游戏状态和存档。

行旅图通过原生dialog或已有暂停弹层呈现；打开时清空移动输入并暂停世界，Esc关闭，关闭后恢复安全状态。触屏按钮必须可直接触达，不依赖hover或键盘。每个新挑战有明确退出/重试、无惩罚恢复和正在进行的进度显示。

验收关注真实游玩：首次玩家30秒内能开始行动；不看帮助也能理解一个挑战；每种身体能力至少有一个独特奖励；完成机关能看出环境前后变化；未访问区域确实保密；39​​0px无溢出、关键按钮不小于约44px；键鼠与触屏完成同一条新主线；旧存档不会把新玩法直接标为完成。

不能用页面截图、字幕数量或新增按钮数代替上述验证。最终以真实输入走通新关卡、观察环境变化及截图复核收口。
