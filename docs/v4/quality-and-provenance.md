# V4 质量升级、素材出处与剩余制作差距

记录日期：2026-11-18。依据本轮[美术计划](art-direction-and-plan.md)、角色/环境/器物报告、已保存的真实 WebGL 画面及当前源代码汇总。本文没有重新运行完整关卡验收或性能基准，不把独立资产预览、截图和测试报告中的局部结果写成最终整体验收结论。

V4 延续林河主线和烁羽角色，主要变化同时发生在可编辑资产与实时画面：角色重新导出两档 GLB，五件器物重建，林下与生活场景补足近景层次，森林环境光和接触遮蔽进入主渲染链，并增加可导出图片的留影模式。原有移动规则、存档协议和文物问答继续沿用。

上述效果各有明确范围：森林 HDR 提供环境照明与反射，不作为全屏森林照片替代可探索几何；GTAO 不是全局光照；Film pass 是项目自写的轻度图像处理，不是胶片扫描或完整摄影色彩流程。常规游玩不启用留影景深，以保留落点和交互目标的可读性。低画质关闭 GTAO、阴影与景深，并减少环境细节活动量；这是一条代码中的降级路径，不是跨设备性能保证。

V4 角色和器物仍以源代码生成、编辑和导出。当前成果不是以概念图充当游戏资产，也没有用面数增加本身作为质量提升的证明。[基线目录](baseline/)保留 V3 源码、模型和画面，角色与环境报告分别提供同镜位比较。

## 4. 与高规格商业游戏/影视制作仍有的具体差距

以下列明当前可见或由实现方式直接决定的边界，以及下一轮需要做的工作，不以「还需优化」代替具体问题。

| 领域 | 当前仍存在的差距 | 真正补齐所需的工作 |
|---|---|---|
| 角色近景 | 羽片虽更细，侧背部仍能看见规则分层与相似轮廓；翼尖仍是薄曲面，绒毛不是逐根 groom。没有羽枝级散射、完整各向异性或次表面透光 | 对头颈、肩部、翼尖做独立雕刻与不对称精修，建立羽簇层级及多方向材质校样；依据平台预算选择更丰富的羽毛卡片或纤维方案，并验证逆光和极近镜头 |
| 动作解剖与二级运动 | 保留的 16 骨骼没有独立膝盖和脚趾关节，急转、落地与抓枝依赖简化约束；羽毛没有逐羽物理响应 | 重做肩肘/腿趾绑定、转弯和落地过渡，补充姿态修形、抓握接触与有限二级摆动；在真实控制器速度变化下逐镜检查，不能只看静态姿态 |
| 环境美术 | 只有少数树形模板，重复仍可辨认；大岩体轮廓较圆整，地面主要靠平铺颜色/法线；木屋有细部但缺少逐构件的受力、磨损和故事性差异 | 优先制作根门、岸壁、稻作木屋等少数英雄场景：独立轮廓、局部坡面细分、贴地碎物、非重复湿痕与磨损；再建立共享资产的尺度和密度规则，而非全场增加同一种灌木 |
| 文物精度 | 没有馆藏多视角测量或授权扫描；金面锤痕、铜鸟背面、玉琮沁斑和石虎崩损为创作，近看仍有程序曲面特征 | 获取足够的授权多视图/尺寸资料，逐件核对比例和负形；为焦点细节做人工雕刻、烘焙与材质标定。若证据不足，继续明确标注艺术演绎 |
| 光影与稳定性 | 使用一套静态森林环境照明、定向光和屏幕空间 AO；不存在动态多次反射、局部反射探针网络或完整体积散射。FXAA 能柔化边缘，不能替代时间域抗锯齿；本报告未验证远处细叶运动时的全部闪烁情形 | 针对实际镜头建立局部环境反射与遮蔽策略，测试薄叶、羽缘和水面在运动中的稳定性；有目标设备实测预算后再选择时间域抗锯齿、体积光或其他照明方案 |
| 水、鱼与植被交互 | 水下色衰减和波纹是着色效果；鱼群是有界游动与避让，植物弯折是近身着色响应；它们没有流体、生态或柔体求解 | 为入水、出水、岸边接触和振翼影响制作少量明确反馈，统一涟漪/水花/声音时序；只对玩家能观察和操作的区域增加模拟细节 |
| 留影与镜头语言 | 留影相机围绕角色运行，并用地面高度限制相机；不是全自由摄影机或完整障碍避让系统。PNG 按当前渲染画布输出，没有超采样高分辨率导出、摄影轨道或镜头剪辑时间线 | 补齐取景碰撞与近裁检查，增加可选自由镜头、曝光/焦点可视化和分辨率独立导出；影视段落另行编排镜头与动作节奏，不把可选景深等同于电影级镜头制作 |
| 声音与表演 | 现有音乐和环境发布混音为单声道合成素材，缺少实地录音和可靠的空间方位声。已有报告没有逐句人工听审结论；供应商语音的生成套餐权利也未闭环 | 完成中文读音、情绪、循环接缝与响度听审；制作授权明确的对白与拟音，按实际空间加入立体声/定位、遮挡和混响分区；将声音授权证据与音色质量分别验收 |
| 资源与设备覆盖 | 当前保留两档角色资产和局部细节降级，但不是成熟的跨硬件流送、GPU 压缩纹理和动态分辨率体系；不能由一个预览窗口推断所有设备体验 | 在关闭其他预览的条件下，独立测生产冷启动、高低档帧时间、内存和长时游玩；针对真实瓶颈再引入纹理压缩、分区载入或更细 LOD，并建立桌面与移动浏览器覆盖矩阵 |

## 5. 验证证据的用途

本轮现有报告分别覆盖不同层级：

- [角色精修报告](character-asset-polish.md)及对应 JSON：实际导出资产、绑定、姿态、足底、湿干和 LOD。它们不是主场景帧率报告。
- [环境精修报告](environment-polish.md)与[碰撞不变量记录](environment-runtime/collision-invariants.json)：环境资产变化、独立视角及对既有路径/碰撞记录的比较。它们不代表所有镜位无穿插。
- [器物报告](relics/README.md)与[独立浏览器记录](relics/browser-report.json)：器物几何特征、孔洞和棚光/侧光校样。其渲染统计不能直接套到完整游戏。
- [主场景局部检查](runtime/polish-check.json)：已有森林照明载入、标题/角色/世界渲染、留影控制与 PNG 输出、退出探索、停栖/水下及窄屏面板检查。不能从这份局部记录推导整条旅程最终通过。

最终交付应另以整合完成后的真实输入全流程回归、生产构建、高低档帧时间和冷启动报告收口。本文不填未经本次独立测量的帧率、加载时间或「全部通过」结论，也不把源码预算当作实际性能。素材来源、画面质量和运行稳定性分别有证据，才能形成可复核的交付判断。

## 最终整合补充

整合近景后继续修正了双翼收拢及潜水体羽穿入基底；角色资料页使用独立骨骼动画时间，并支持俯仰环看和滚轮拉近。景深使用主场景透明裁剪深度的独立RGBA副本，避免叶片矩形边界和帧缓冲反馈；低画质禁用景深控件并说明。高低画质切换同时更新renderer与composer像素倍率。

[后台器物构建](relics/worker-loading.md)让复杂器物生成脱离UI线程，传输真实几何和材质；不把这一优化说成首场景零等待。[最终整合验收](verification.md)记录实际生产冷启动、性能抽样和全流程结果。
