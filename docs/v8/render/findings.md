# V8 渲染与相机：复现、修正和实测边界

## 现象分解

用户反馈移动抽帧。V7 的静止六秒采样不能证明运动流畅，本轮先用冻结 V7 源码、15 秒真实 W 输入和只调整朝向的辅助，穿过四个区域。初次记录有很大的机器/冷态波动：根林 342 帧、湿地 316、风崖 223、聚落 363，根林 p95 间隔 117 ms。保留 [初次移动基线](baseline/profile.json)，不将其当作不可变的机器基准。

下文的“风崖”沿用了性能脚本的 scarp 标签，具体采样点为路线约 0.39，实际画面处在希石双廊/石径附近；它不代表完整山沟、峭壁区域的覆盖。

主循环每帧仅记录数字和分段耗时，不在逐帧采样里调用遍历场景的 snapshot。CPU 采样另外执行，文件为各目录 cpu.cpuprofile。计时包装存在开销，子阶段为包含式计时，不能把各列直接相加。

另一种微顿由运动核心 90 Hz 物理步与显示帧不对齐导致，不等于 GPU 掉帧；此项由运动模块和主循环增加表现插值。长帧被旧主循环截成 .04 秒造成的慢行则由主循环单独修正。

## 相机精确查询

现有根林障碍含 41,046 三角形的扫描树桩、11,622 三角形古木与每实例 3,064 三角形的树干。候选镜头、中心和近裁角反复进行完整三角形遍历，是真实 CPU 热点。

新增 src/v8/camera-query.js：只为相机提供精确的最近命中查询。使用 [three-mesh-bvh 官方实现](https://github.com/gkjohnson/three-mesh-bvh)，固定 0.9.18，MIT，peer Three >=0.159，当前 Three 0.185。许可保留于 public/licenses/three-mesh-bvh.txt。安装使用 ignore-scripts，没有全局修改 Mesh 原型。

- 间接 BVH 索引只在共享缓冲的查询几何上构建，不重排渲染索引，不减少模型面数。
- 保留 near/far、材质面方向、分组、drawRange、layers、递归停止及自定义 raycast 语义。
- 实例版本、数量、世界矩阵、几何更换与顶点版本使缓存失效；普通和交错属性分别追踪属性/底层缓冲 identity 与 version，实例世界球只用于有限线段的保守候选排除。
- 非均匀父缩放与子旋转形成剪切时，使用实际射线方向的世界长度换算 near/far。此测试先出现漏命中，修正后通过。
- 普通探索继续避开陶案/陶器；陶作近景仍排除主体自身，防止 V7 曾出现的器腹特写问题。

7 组新查询测试加 6 组原近裁面测试通过，覆盖数百条等价射线及镜头贴墙、内腔、导演回退。独立同行代码审查发现了交错 position 缓冲更新、相同 version 的 instanceMatrix 属性替换这两种缓存漏判，真实属性位移/换缓冲回归均先红后绿；其余材质、剪切 near/far 与反射 finally 恢复审查未发现明确项目内缺陷。实际树桩的 [CPU 配对基准](camera-benchmark.json)：同样 600 条有限射线，571 次命中全部等价；六轮交替顺序原生查询 3.28–3.48 秒，BVH 8.28–14.71 毫秒，一次构建 58.8 毫秒。这只是树桩查询成本，绝不是游戏 FPS 提升几百倍。

## 仅替换相机的实页配对

[before](camera-before/profile.json) 与 [after](camera-after/profile.json) 均固定 V7 HTML、源码、GLB 和运行素材，仅 after 替换相机查询。每区相同起点，15 秒 W 输入，末点差小于 0.64 m；不是逐帧完全相同的录像回放。Edge 157、1440×900、DPR1、AMD Radeon(TM) Graphics / ANGLE D3D11，单个自动化 3D 页面。不能保证用户的其他应用没有系统负载。

| 指标 | before | after |
|---|---:|---:|
| 根林最终近裁检查 CPU 中位 / p95 | 5.0 / 12.5 ms | 0.2 / 0.4 ms |
| 根林整段主逻辑 CPU 中位 | 11.5 ms | 4.2 ms |
| 根林 15 秒记录帧数 | 685 | 853 |
| 湿地 GPU 查询中位 | 15.38 ms | 19.80 ms |
| 风崖 GPU 查询中位 | 18.76 ms | 25.02 ms |

GPU 数据来自非阻塞 EXT_disjoint_timer_query_webgl2，舍弃 disjoint / 未完成查询，包含该查询范围的 GPU 时间，不是 CPU 提交耗时。after 在湿地和风崖的 GPU 时间反而上升，帧数下降；绘制和三角量约 ±1%，尚未证明原因。不能挑根林的好结果就宣称全场景帧率改善。可靠结论是相机 CPU 热点减少，GPU 总预算和跨时段波动仍需后续测量。

## 反射变换复用

Three 在主 render 开始已更新场景世界矩阵。水面 onBeforeRender 的内部 render 原先再次遍历整棵场景；本项目没有其他 onBeforeRender 修改物体变换。现在仅在内部反射渲染期间暂时关闭 scene.matrixWorldAutoUpdate，并在 finally 恢复原值；反射相机仍独立更新，独立 warmup 仍完整更新。没有降低反射分辨率、刷新动态反射频率或隐藏对象。

新增三个测试覆盖：同帧动态物体矩阵相同且不重复遍历、原本手动矩阵策略保持、内部渲染异常时恢复。与七个反射缓存/更新测试共十项通过。尚不将这个重复遍历消除称作已测得的全游戏 FPS 提升。

## 实景几何回归

scripts/review-camera-query-v8.cjs 已完成五区、高→低→高三次质量往返的 2,160 条实际场景有限射线比对：命中/空、距离（1e-5 容差）、物体、实例全部与原生一致。八角陶作相机距目标 3.332–3.345 m，实际 E 进入、Esc 退出均成立；WebGL 错误为 0、没有 pageerror。[原始记录](camera-regression/results.json) 与 [陶作截图](camera-regression/pottery.png) 保留。目视截图中器口、器身及右侧制作界面完整可见，没有进入器腹。

## 07:09 UTC 整合快照的像素预算 ABBA

脚本 scripts/profile-pixel-budget-v8.cjs 对同一个运行页面作 A→B→B→A：1920×1080 CSS 视口、high、A 的 DPR1（207 万 3D 像素）、B 的 DPR1.5（467 万）。通过 CDP 设备 DPR 驱动正常 applySettings；模型、灯光、贴图、反射设置均相同。每轮根林与风崖各静止 8 秒、真实 W 前行 8 秒，只有测试朝向辅助；不在记录段写角色位置。主源码 SHA256 记录于 [完整结果](pixel-budget/profile.json)，Edge157 / AMD Radeon(TM) Graphics，16 段均完成。该快照早于本轮最后的枝干法线与角色肩根修正，结论用于隔离像素成本；最终资产的连续运行另以正式 soak 评价。

| GPU 每帧中位时间 | A 首轮 | B 首轮 | B 次轮 | A 返测 |
|---|---:|---:|---:|---:|
| 根林静止 | 12.87 ms | 22.32 ms | 23.56 ms | 13.30 ms |
| 根林前行 | 12.87 ms | 21.87 ms | 26.20 ms | 12.11 ms |
| 风崖静止 | 14.70 ms | 23.28 ms | 24.77 ms | 13.76 ms |
| 风崖前行 | 14.20 ms | 25.24 ms | 30.92 ms | 15.04 ms |

静止场景绘制量精确相同：根林 179 calls / 1,490,662 triangles，风崖 459 / 2,394,646。移动段中位三角数差约 0.4%，是实走采样差异。A 的这些短段平均观察为 56–60 fps，B 为 27–41 fps；A 返回后恢复，说明像素成本确为这台设备的压力来源。不能从 8 秒片段推广为整个游戏稳定 60 fps。B 次轮有较大波动，仍不把主机调度/热态等尚未分清的长尾全部归因于游戏。

第一次 A/B 尝试在再次设置 DPR 时读回值与期望不一致，脚本主动退出；原始数据保留于 first-attempt-incomplete.json，未混入完成结果。去除段间截图（其可能恢复 Playwright 原设备配置）、每次显式清除/设置 CDP metrics 并等待 devicePixelRatio 后，四轮全部完成。该失败属于测量装置一致性，不是游戏运行故障。

据此实现了独立 src/v8/render-scale.js，由主任务接入可见设置及持久化：balanced 默认预算 2,073,600 个 3D 像素，detail 保留旧 high DPR≤1.5 / low DPR≤1。balanced 仅在 resize/设置改变时计算比例，避免逐帧清晰度波动和渲染目标重建；.5 是缩放下限，因此 4K 恰为 1080p 渲染，超过 4K 的极大窗口仍可能超过预算。原生 DPR<.5 时保持原比例，避免反向放大。四组尺寸契约测试通过，覆盖高低档、手机/桌面/4K/8K、无效缓存值。

不能把相机单变量实验或这次像素 ABBA 当作最终全版本性能承诺。scripts/soak-motion-v8.cjs 的 20 分钟正式执行已完成，阶段、checkpoint、真实键盘和 5 Hz 轻状态采样方法写入运行结果，详情见下节；无调试辅助的自然游玩另由主任务检查。

## 最后几何版本与 20 分钟连续运行

最终森林枝干、树根、竹秆外绕序及角色第四版确认后，五区 2,160 条同版 Three/相机查询再次全部一致，八角陶作亦通过。camera-regression/results.json 记录 main、world、traversal、bamboo、profiled-tubes、查询模块和高精角色的文件哈希。reference-root/marsh/scarp/hamlet/bay/bamboo.png 是检查点参考图；它们有开发定位，因此部分字幕/发现卡仍属于前一个地点，不能把这些图当作自然主线游玩证据。目视检查发现湿地生态提示卡与行动条重叠，已交主任务作长测之后的 CSS 修正。

正式长测从 **2026-11-19 08:07:33 UTC** 开始，持续 **1,209.955 秒（20 分 9.955 秒）**，记录 **55,933 帧**。仅一个 Edge 157 三维页面、AMD Radeon(TM) Graphics / ANGLE D3D11、1920×1080 CSS、设备 DPR1.5、高画质＋均衡清晰度（实际 3D DPR1）。主程序与世界/角色/统一计时源码冻结；64 份实际服务模块哈希和两档 GLB 哈希保留在 [原始结果](soak/results.json)。高精 GLB 为 5,379,860 B，SHA256 `0592d162b5a8f6231e51cff3820a93c08a4d305f61ea6c5ff38f328eb7209138`；低精为 3,382,128 B，SHA256 `8340274cdfc28c1149f0f1991d1e80917251615c8a5b93803798c88a17f6fe71`。

五个采样中心为路线距离 30/110/180/270/360 m，每区往返约 ±12 m：80 s 地面移动、80 s 持续飞行及真实耗尽后恢复、60 s 交替走/快走/跳跃/闪身、10 s 暂停、10 s 恢复。区间转移各有一次明确记录的开发检查点；区内没有位置/资源写入，只通过实际键盘输入及朝向下一路径点的 yaw 辅助。飞行目标为地面/水面较高者上方 3.2 m，并受场景上限约束。状态约 5 Hz 读取，RAF 帧长逐帧保存，每 10 s 抽取 CDP/渲染资源/音效池指标；没有逐帧完整 snapshot、GPU timer 或强制 GC。

原始帧、每阶段分位数和最慢 20 帧的近邻状态保留在 [汇总](soak/summary.json)。例如根林第 99.13 s 巡风有 283.8 ms 帧，石径约 534 s 有 191.8/184.1 ms 连续长帧，聚落约 912 s 有 144.6/168.9/144.9 ms 一组长帧；它们不能统称为启动加载。近邻状态采样与慢帧有时间偏差，已记录 offset，不用于虚构精确根因。

- 所有页面、console、请求失败、WebGL 错误均为 0；位置/羽力/氧气有限值、地形下限/飞行上限、暂停冻结与恢复、各区最低实际行程断言通过。
- 五区均观察到一次羽力约 0.0098 时自动结束巡风、转入滑翔，随后通过实际降落恢复；后续飞行按低羽力主动休息。五次 10 s 暂停中位置、羽力、氧气不变，音频状态同步恢复。
- 约 3,763 m 是同一小段的**累计往返采样行程**，不是新增地图长度。湿地出现一次预设路径碰障：第 292.63 s，约 `(3.152, -0.035, -78.369)`，5 s 位移仅 0.266 m；按既定方法反向＋1.2 s Space 后继续，完整保留事件，没有区内开发定位绕过。
- 此巡游实际覆盖 grounded/flying/gliding/rising/falling，**没有覆盖游泳、潜水或停栖**；这些需要主任务独立场景/真实输入检查。模式样本数与观察到的模式进入次数分别记录，不混为一谈。
- 运动音效活动来源峰值 3，所有 cue 来源峰值 3；缓存随首次使用表面/动作从 16→24→32→36，后段稳定 36，最终活动来源归零。
- Renderer 资源计数随首次见到区域从 312→365 个几何、80→83 张纹理；后三区在各自 4 min 内分别稳定为 358/362/365 几何，纹理保持 83。CDP JS heap 每区低点约 28.6–30.3 MiB、高点约 54–64 MiB，出现自然 GC 回落，没有连续爬升迹象。没有强制 GC、也没有测量所有 GPU/WebAudio 原生字节，因此不把它称为全面的“零泄漏证明”。

GPU 已在长测结束后关闭并交回主任务，后续无调试驾驶、CSS 生态卡排布和生产构建检查另行执行。本轮可靠完成了相机查询热点、重复反射变换、帧调度与可见像素预算的修正；长测保留的聚落巡风负载和偶发长帧仍是后续性能工作的真实边界。
