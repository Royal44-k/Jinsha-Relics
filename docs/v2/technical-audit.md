# 金沙探索游戏 V2 技术审计与实施约束

日期：2026-11-18。范围：只读检查现有产品代码，运行隔离诊断脚本；本轮没有修改 `src/`、`index.html` 或启动器。以下方案是建议与待验收目标，不是已实现能力。

## 1. 结论

用户看到的简陋白页有明确结构性原因，已经复现。现有版本的全景浮岛也并非只需增加雾就能转为探索：世界、导航、图鉴、相机、存档、音频都围绕一个一次性建立的小型开放空间组织。V2 应保留渲染与交互基础，将世界换成有遮挡、有分支、有局部自由的连通关卡，并把资产加载和叙事揭示分成两个独立系统。

优先顺序：可靠首绘 → 一段真正可探索的灰盒路线 → 一名完成雕刻/绑定/动画的角色 → 一段高品质视听章节 → 其余章节。不能再用测试通关替代美术和探索体验验收。

## 2. 白页根因与可复现证据

| 位置 | 观察 | 后果 |
|---|---|---|
| `index.html:3` | 只有 meta/title/favicon，无内联关键 CSS，也无源文件样式链接 | `theme-color` 只设置浏览器界面主题色，不能设置文档背景；首绘仍可能白底 |
| `index.html:7–26` | 加载层、菜单、HUD、弹窗、结局都直接写入 HTML，隐藏依赖 `.hidden` | 样式未就绪时本应隐藏的界面也进入普通文档流 |
| `src/main.js:10` | 唯一基础样式通过 JS 模块导入 | Vite 开发模式下需等待模块获取/执行后注入 CSS，延迟或失败会暴露裸 HTML |
| `src/style.css:2,5` | 背景、SVG 尺寸、`.hidden`、加载层定位都在这份外部样式 | 无样式时白底、默认黑字、放大的品牌 SVG；并非用户看错 |
| `scripts/launch.cjs:9–12` | 启动 Vite 开发服务器，而非生产产物 | 每次打开都经过开发期模块图；部署预览与交付入口没有分离 |
| `src/main.js:44–61` 与 `src/world.js:128–246` | 同步准备环境贴图并生成/合并整片场景 | 主线程长任务会使 DOM 动画停顿，加载页即使出现也可能卡住 |
| `src/main.js:244` | 在整个模块执行尾部，用 500ms + 800ms 定时隐藏加载层 | 不是资源就绪进度；没有网络/解码/上传/着色器预热/首帧检查 |
| `src/style.css:1` | 字体为本地 WOFF2，`font-display:swap` | 可保留；字体会造成短暂替代字形，但不是裸白页的首要原因 |

### 本次隔离实验

使用新建 headless Edge 上下文、1440×900、独立 Vite 端口 5197，对 `/src/main.js` 人为延迟 3000ms。脚本结束时浏览器和服务器均关闭。该实验用于放大启动时序问题，**不是用户实际网络耗时测量**。

- 模块等待期间：`bodyBackground = rgba(0,0,0,0)`，`bodyColor = rgb(0,0,0)`，加载层 `position = static`，HUD `display = block`，引擎尚未建立。
- 截图中明确出现白底黑字和放大的黑色 SVG。[白页证据](cold-start-unstyled.png)
- 模块就绪后：背景变为 `rgb(11,28,29)`。[完成加载截图](cold-start-ready.png)
- 延迟实验记录了约 2461ms、2562ms 的长任务；后续普通重载记录约 1574ms、401ms 长任务。它们说明同步 CPU/GPU准备工作存在停顿，不可直接当作所有设备的性能。
- 普通重载采样约54fps、100次渲染调用、1,619,872个渲染三角形计数。这里是 `renderer.info` 的整个帧计数，包含阴影/后期等绘制，不等同于独立模型三角形数。

复现文件：[audit-startup.cjs](audit-startup.cjs)、[startup-audit-metrics.json](startup-audit-metrics.json)。在项目根目录执行 `node docs/v2/audit-startup.cjs`。脚本只生成诊断文件，不编辑产品源文件。

### 首屏修复方案

1. HTML 内联一小段关键 CSS，立即确定 `html/body` 的暗色背景、加载壳占满屏幕、品牌 SVG 的固定尺寸、非启动界面的原生 `hidden` 状态。壳使用系统字体和内联矢量，不依赖 WebGL、模块或网络字体。
2. 先显示精心制作的静态角色轮廓/金箔纹样、真实状态文案；等轻量角色展台就绪后平滑接管。首页只呈现角色和近景，不把整张地图当首页背景。
3. `bootstrap` 只负责状态机：`shell → manifest → download → decode → gpu-ready → first-frame → ready`。只有在必需资产、碰撞体、角色控制器与首帧都成功后，启程按钮才可操作。
4. 若有可靠清单字节数，显示真实下载进度；字节数未知时显示“准备角色”“构建场景”等阶段，不制造匀速假百分比。Three.js `LoadingManager` 的 item 数并不代表下载字节或GPU工作量。
5. 用 `compileAsync()` 做当前场景材质预热，至少渲染一个实际帧后再移除遮罩；仍需测量驱动和纹理上传卡顿。把离线可完成的程序生成和几何合并转到资源制作阶段。
6. 模块、资源、WebGL失败都落到同一美术风格错误页；可重试、切换轻量模式、查看静态角色资料。不能让失败变成无限旋转。
7. 正式入口提供已构建的静态产物及内容哈希缓存。开发服务器保留给开发，不成为面向玩家的默认启动链。

Three.js 官方支持 glTF 资产加载、加载管理和异步着色器编译；编译预热需在灯光和环境配置就绪后进行。[WebGLRenderer](https://threejs.org/docs/pages/WebGLRenderer.html)、[GLTFLoader](https://threejs.org/docs/pages/GLTFLoader.html)、[LoadingManager](https://threejs.org/docs/pages/LoadingManager.html)

## 3. 为什么现有世界不能产生“未知”

- `world.js:149–150` 一次建立4个主岛和6个远岛；`main.js:61` 在启动时全部加入同一 scene。
- `world.js:130–132,230` 将所有地景按材质跨区域合并。即使一个区被墙遮住，整个合并网格仍可能跨多个区，难以独立裁剪、卸载和统计预算。
- `main.js:42–43,198` 首页高位远镜头刻意展示全局；`main.js:215–218` 允许升至30单位，容易越过普通遮挡。
- `main.js:99,235` 立即建立全部文物世界标签，显示只检查屏幕位置与距离，没有探索状态和视线遮挡。
- `main.js:146` 未发现图鉴提前列出全部名称并可选引路；`main.js:186` 地图无探索迷雾，全部岛和文物都标出。
- `main.js:203–205` 自动引路直接沿目标向量飞行，没有可通行路径、门洞条件或章节状态，未来弯曲路径会被穿越/绕过。
- `main.js:223` 区域仅按 `x/z` 阈值判断，不能表示曲线路径、支路、回流捷径、洞内外和上下叠层。

因此“下一地点靠近才显现”应定义为：玩家已能自由移动，但当前视线由地形遮挡；近处先出现声源和光的线索，经过一两次转折后地标展开。**资产应在被看见之前加载好**，不能在眼前凭距离突然生成房子。

## 4. 连通关卡与渐进揭示架构

### 4.1 路线建议

用“主线串联的探索庭院 + 短支路 + 已发现后开启的回路”替代放射状岛群。下面只是可落地的技术样板，不固定最终艺术命名：

```text
角色首页 / 微光苏醒
        ↓
A 苔林低径 ── 可选支路 A1：听风空穴
        ↓ 树根S弯，远处只见反光
B 临水断岸 ── 可选支路 B1：低处石纹
        ↓ 穿过跌水幕后，视野压窄再展开
C 玉光廊庭 ── 开启回到B的短环路
        ↓ 曲折岩隙，先听到金属泛音
D 金面记忆庭
        ↓ 先局部圆弧，再完整揭示日轮
E 日轮高庭 / 终章
```

每庭院允许绕行观察、寻找不同入射光和小发现；主线目标始终在远端，引导不等于轨道锁定。支路可以通向可读的死端奖励，再汇回主路，避免把全开放地图伪装成探索。

### 4.2 三个独立状态

| 状态域 | 示例 | 作用 |
|---|---|---|
| 资源 | `unrequested / fetching / decoded / gpuReady / resident / evictable / failed` | 处理网络、内存、显卡上传 |
| 探索 | `unknown / hinted / discovered / mastered` | 控制地图、标签、图鉴、语音与剧情 |
| 显示 | `occluded / silhouette / visible` | 由实际几何遮挡、雾、视线与剧情条件决定 |

“已加载”不等于“已发现”；“已发现”也不等于必须每帧渲染。不可用一个 `visible` 布尔值承担三套职责。

### 4.3 分区资源清单

每个区保存：稳定 ID、包版本、GLB/贴图/声场清单及字节数、bounds、入口/出口触发体、碰撞体、可通行区域、相邻区、预取触发体、近景/中景/远景LOD、叙事事件、存档安全点。离线脚本检查清单完整性。

当前区、上一区、相邻预取区保持常驻，远区从内存回收。用户返回时重用本地缓存。跨区共享材质、角色、音频和环境贴图由引用计数拥有；不能卸载一个区时顺带释放其他区材质。现有 `palette` 全局对象须纳入显式资源所有权。

合批原则改为“区内按材质合批，植被按区实例化”。不再跨全地图合成一个巨型材质网格。先测CPU/GPU再决定是否需要更细分的网格单元。

### 4.4 无突现的具体规则

- 使用树根墙、河弯、岩隙、局部高差和前景叶片组织遮挡；雾增加深度，不负责遮盖未加载资产。
- 临近地标先出现小面积轮廓、反射或声源；临界转弯后才展开全景。确保每次揭示能在静音状态下依然成立。
- 摄像机可查看局部环境，但角色飞行高度受真实冠层/洞顶/地形设计控制，不允许从低径直接垂直爬升俯视全章节。给可理解的风流/攀升规则，避免无解释透明墙。
- 地图仅画已发现路径；未知区不显示确切地名与文物图标。图鉴未发现项只显示数量或空位，名称在观察后揭示。
- 引路改为局部提示：最近已知可通行转折、风声或羽片方向；可访问性自动行进沿经过验证的路径节点前进，不能穿过未发现区直达文物。
- 预取按最坏可达时间算：`领先距离 ≥ 最大速度 × (下载 + 解码 + 上传 + 安全余量)`。例如最大速度12m/s、全链路预估8秒，则至少提前96m触发；短关卡装不下这个距离，就在当前区入口预取下一块、减小资源包或调整速度。
- 网速不足时，保留当前可探索庭院；明确显示准备状态或重试入口。不要临时在玩家面前生成遮挡墙，不要让未完成碰撞加载的空区可进入。
- 可选小物件用短时抖动淡入并在遮挡后切LOD；宏观山体/墙/文物必须先就绪，禁止透明渐显穿帮。

## 5. 角色、相机与物理

### 当前可用与不足

- 现有角色 `main.js:85–95` 是球/锥/椭球/圆环组合，只有旋翼式摆动。它可以作为灰盒尺寸代理，不能充当精细角色成品。
- 目前相机有射线缩距 `main.js:71`，玩家有少量轴对齐代理推离 `main.js:72`，应保留经验但重建碰撞数据。只有树干、石门和玉门被覆盖，不能支撑整条曲折关卡。
- 固定角速度、平滑速度可复用；`dt` 截断和单次位置推进不替代高速扫掠检测。单根相机射线也不能保证近裁面四角不穿墙。

### 建议规格

角色从可审阅三视图/表情板开始，经真实三维雕刻、低模拓扑、烘焙、骨骼/形变、材质、动画导出。AI概念图只承担设计，不当作已经完成绑定的三维资产。保留可辨的脸、羽翼/耳冠、金箔细节和重量感，发光控制在轮廓与小面积，不把角色烧成白团。

首批动画至少包括待机呼吸、观察前探、启动加速、转向倾身、急停回望、发现惊喜、共鸣施法、失落/害怕、恢复勇气；移动状态之间做动作混合，而不是同一正弦摆动贯穿全部情境。小精灵表演也承担无字引导。

控制采用贴地悬浮/短距跃迁/滑翔的可读规则，保留自主前进和转向。固定时间步处理角色胶囊扫掠、滑移、头顶探测和掉落恢复；渲染帧插值。地面不再是岛圆半径+固定高度，而是简化地形碰撞网格。

相机使用肩后跟随、朝向前视与速度响应；用球形扫掠或多射线覆盖近裁面尺寸，撞墙时快速收缩、离墙后慢速恢复。镜头过近时先淡化角色自身或特定前景，不透视展示未知房间。进入揭示区只给轻微构图辅助，玩家转镜可立即接管，不能抢控制硬播镜头。

存档至少包含 `schemaVersion / checkpointId / chapterId / discoveredIds / puzzleStates / dialogueFlags / safePose / settings`。v1进度留在旧键，v2另开槽；不擅自删除旧档。恢复先加载当前区与碰撞，再校验有限位置、已解锁路径与安全落点，失败回最近检查点，而非全局夹取坐标。

## 6. 音频管线

现有 `audio.js:120–200` 是风噪、正弦持续音与稀疏五声音阶，适合原型；没有章节音乐、音乐段落/循环点、速度与探索情绪参数。`audio.js:257–275` 每次选择系统首个中文声线、固定语速音高；不同电脑可能完全不同，并不满足两位角色稳定、可辨识的配音要求。主逻辑 `main.js:222` 在飞行时播放脚步，也会破坏身份感。

建议保留：用户点击解锁音频、平滑音量、静音、页面隐藏暂停、音源释放。替换：BGM内容、配音、音乐调度、叙事触发。

- 分总线：Music、Ambience、SFX、Narrator、Spirit、UI；分别可调，主总线限幅。
- BGM离线制作/授权导出等长、节拍对齐的基础/探索/悬念/揭示层；通过关卡和行动参数混合。跨区在音乐小节边界或预设过渡点切换，不用随机定时器生硬跳段。
- 风、水、鸟、洞穴混响使用区域和距离参数；旋翼、衣羽、共鸣替代飞行脚步。只有真正接触地面才播脚步。
- 两条稳定身份声线预生成并打包：一位叙事者、一位小精灵；每条素材关联角色ID、文本、时长、字幕片段、触发条件、优先级、冷却和是否可重复。
- 调度器遵守剧情对白 > 必需引导 > 旁白知识 > 随机闲语；对话期间音乐自动压低，避免相互打断。用户离开触发区、开菜单或暂停后的语音规则必须明确。
- 短音效可解码为 AudioBuffer；长BGM与大量对白不要一次全部解码为PCM，以免比压缩下载体积大数倍。下一段对白与相邻区预取，提供兼容音频格式和本地字幕。
- 系统TTS只保留为明确标注的辅助降级。真人/合成声音都要确认可用授权，不虚构已有配音成品。
- “古蜀文化氛围配乐”与“考古原声复原”分开表述，乐器组合的史实由文化研究文档确定。

音频解锁应在用户手势下恢复 AudioContext；浏览器拒绝播放时，保持静音可玩而不是卡住开始流程。[MDN AudioContext.resume](https://developer.mozilla.org/en-US/docs/Web/API/AudioContext/resume)

## 7. 初始制作预算与测量方法

以下是首个精品章节的建议上限，需通过选定参考设备实测校准，不是现状承诺。质量先在一个30–90秒可重复路线稳定，再扩建章节。

| 项目 | 桌面基线建议 | 轻量档建议 |
|---|---|---|
| 首绘壳 | 内联关键样式+SVG不超过30KB；静态图尽量≤200KB | 同一壳 |
| 首个可操作场景必要下载 | 目标≤8MB压缩传输，非全章节 | 更小LOD与纹理，目标≤5MB |
| 当前可见三角形 | 约≤80万，阴影pass另计 | 约≤30万 |
| 绘制调用 | 主画面目标≤150，记录总pass成本 | 目标≤90 |
| 角色LOD0 | 约3–5万三角形，关键部位法线/材质充分 | 约1–2万 |
| 屏幕分辨率 | DPR上限1.5，动态分辨率 | DPR1或更低 |
| 动态投影灯 | 主要1盏，辅光优先烘焙/无阴影 | 1盏低分辨率或烘焙 |
| 纹理 | 角色2K，少量特写4K，其余1K/2K；压缩到设备支持格式 | 512/1K，限制同时常驻 |
| 资源常驻 | 当前/前一区/下一过渡区；在美术预算表估算GPU纹理字节 | 更短预取窗口与更小LOD |
| 帧率目标 | 1080p、选定中档独显：p95帧时≤22ms，p99≤40ms | 选定移动/核显：p95≤40ms |

浏览器无法可靠统一读取所有设备的精确显存。应以资产尺寸/格式估算纹理显存，结合 renderer.info、JS内存（可用时）、上下文丢失与长时间往返测试，不能只展示“FPS 60”。

glTF可携带标准材质/动画；几何压缩与纹理压缩均要计算解码成本。KTX2转码需要与当前renderer匹配的支持检测，解码器/转码器也打包本地；资源卸载需要关注图像位图的显式释放。[GLTFLoader](https://threejs.org/docs/pages/GLTFLoader.html)、[KTX2Loader](https://threejs.org/docs/pages/KTX2Loader.html)

## 8. 模块重用与重写边界

| 现有模块 | 建议 |
|---|---|
| Vite/Three.js、基础Renderer、色调映射 | 保留并拆到 `render/`；不为“影视感”盲目换引擎 |
| `world.js` 全局程序场景 | 重写为分区场景加载；程序模型仅保留为灰盒或小配件 |
| `main.js` 大脚本 | 拆为 bootstrap、game-state、controller、camera、streaming、exploration、dialogue、ui |
| `data.js` 文物资料和来源 | 文化复核后重用；坐标与发现状态移出资料正文 |
| 图鉴文字/来源/检视交互 | 重用概念；锁定项避免剧透，预览不重建过多WebGL上下文 |
| localStorage | 保留介质，新增版本化状态和安全点；迁移保留旧档 |
| `audio.js` 音量/静音/释放 | 保留基础；作曲、声线与调度重写 |
| `style.css` 品牌基本色与中文字体 | 可复用；启动壳、角色首页、资料卡需重新设计 |
| smoke-test | 保留通关思想；重写为路径/渐显/首绘/声音状态验收，避免自动引路替代玩家体验 |

## 9. 分阶段执行与可测验收

### P0：可靠启动（先解决用户直接遇到的问题）

- 产物：静态启动壳、资源状态机、错误/重试页、正式静态启动入口。
- 验收：人为延迟JS10秒、CSS10秒、字体失败、WebGL禁用、任一必要资产404；从首次HTML内容绘制开始不出现白底或裸界面、不展示可点击但无响应的启程按钮；所有失败有正确状态。
- 正常网络目标：参考桌面、10Mbps/80ms/冷缓存，首次可操作≤12秒；此阈值须带设备和样本次数报告。

### P1：探索灰盒（不先堆精美资源）

- 产物：A→B→C的S形连通路线、两条短支路、一次回路、五个揭示点、基本角色控制和稳健相机。
- 验收：至少三名未看过地图的人无口头指导能前进；首次进入看不到全局地图、远区标签或最终日轮；至少两个“先听到/见线索、转弯后才展开”的明确时刻；反向行走与高速通过不会穿墙、跌落或卡死。

### P2：一个精品视听章节

- 产物：最终角色、完整角色资料卡、1套高质量地景、关键文物特写、完整动画、旁白/角色双声线、分层BGM。
- 验收：近景材料可读，角色脸部不过曝；低速/高速/停止动作可区分；暂停恢复对白不重叠，字幕匹配；声线身份由不看字幕的试听者区分；用同一镜头与参考素材做人工美术评审。

### P3：资源流式加载与性能

- 产物：区包、LOD、预取/回收、缓存、路径预测和诊断面板。
- 验收：单区资源额外延迟5秒时不出现空地/无碰撞区；来回穿越边界20次无重新配音轰炸、长期内存增长或错删共享纹理；后台切回、上下文丢失、保存恢复都能进入安全状态；p95/p99帧时达到所选档位目标。

### P4：扩建章节、叙事闭环与回归

- 产物：其余章节、不同探索动作、终局、无剧透图鉴、生产包。
- 验收：一次手动通关、一次可访问性辅助通关、一次支路回溯通关；刷新/跨区/中断恢复后发现状态正确；旧存档不丢失；重点检查首屏、门洞、镜头、音频和每个发现瞬间，不能仅检查“无JS报错”。

## 10. 需要管理的真实风险

1. 精细角色与专业声音是资产制作任务，不能仅通过增加程序几何和Bloom实现；在没有资产前不得把原型截图称为影视成品。
2. 新素材一味高分辨率会把白页变成长加载；要先有区包预算和可用的一级LOD。
3. 有雾不代表有探索。玩家的高度、视线、标记和声音都会泄露布局，需要共同设计。
4. 大面积透明雾、叶片、光束在移动端可能受到像素填充率限制；粒子数量低也不保证快。
5. 历史风格音乐不等于考古还原；品牌角色参考不等于可直接复制官方IP。
6. 现有自动化仅验证可通关、状态与界面，不能证明角色有生命、音乐好听、发现有惊喜。后面三项要有明确的人工评审环节。
