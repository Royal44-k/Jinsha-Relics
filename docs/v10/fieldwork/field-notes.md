# 从河床剖面到九处遗存

第一站让玩家用刷毛读一条线。第二站把这条线变成一段可航行的河。第三站再把河岸上的古根记录成有尺度的图。烁羽带走的每一页都有可追溯的观察过程。

| 地点 | 玩家动手做什么 | 怎样判断结果 |
| --- | --- | --- |
| 滨河探方 | 来回扫去两个取样窗的浮土，换记录针标记粗砂下缘 | 两窗需要实际覆盖刷痕。视觉素材中的暗色层上缘逐列对齐到判定曲线。可以拔针重记 |
| 古河道渡口 | 控制竹排横拨、加速和减速，绕过浅滩，在左右两岸分别靠泊 | 水流会把竹排送向下游。吃水线触及沙脊时必须转向，靠到测水桩才记录 |
| 古木测绘台 | 环视四个根端，系住两桩，收放测绳，扣绳读数 | 实际桩位决定跨度。绳短时够不到桩，绳长时出现垂弧。演示根盘最宽的一对约为 6.08 米 |

竖屏的两个局部放大窗与总剖面共用同一张可擦除的浮土层。低帧率下，行舟按经过的时间拆成小步推进，慢设备可以降低绘制分辨率。测绘台静止时会保持已绘画面，环看、调整绳长、载入扫描图像和改变视窗尺寸才重绘。

## 考古依据与艺术制作

金沙遗迹馆展示大型树根与考古现场，祭祀区沿古河道南岸分布。馆方资料记载第 18 号遗迹有九处方柱遗存，原柱边长约 40 厘米，南北柱距约 1.9 米，东西柱距约 2.9 米。游戏的方孔与辨迹时出现的复原柱共用九个柱心。水路、测量数值、测绘工作台、器物转场和木构显影属于交互演绎。[金沙遗址博物馆遗迹馆](https://www.jinshasitemuseum.com/node/216)

关卡设计借鉴了《Heaven’s Vault》用推断推动下一段旅途的方式，以及 Discovery Tour 允许玩家在场景中自主停留、观察历史细节的做法。这里把推断转成两种具体反馈，针能否落在可见层界上，绳能否在正确的两端之间绷直。[inkle 的 Heaven’s Vault 项目页](https://www.inklestudios.com/heavensvault/) · [Ubisoft Discovery Tour](https://www.ubisoft.com/en-us/game/assassins-creed/discovery-tour)

探方取样面使用本作原创河积层美术。凹形探方沿岸展开，三面土壁与缓坡共边，入口保留原地形并增设四级踏面。近景古根以 Rob Tuytel 的 Tree Stump 01 树桩为细节来源，外围根系、测桩、曲线绳和判定另行搭建。连续地图使用保留原纹理坐标与接缝的降面模型，共 5,402 个三角面。该树桩为自然环境素材，游戏未取得馆藏古根扫描。[Tree Stump 01](https://polyhaven.com/a/tree_stump_01) · [Poly Haven 授权](https://polyhaven.com/license)

## 可复查的实玩记录

- [近景交互结果](interaction-results.json)记录桌面键鼠及手机视窗触控的实际输入、错误操作、收卷与退出清理。
- [剖面材质复核](trench-material-results.json)额外采样标记线上下的真实画面像素，验证浅砂与暗带的可见位置。
- [九处地标检验](map-landmarks.json)记录每站几何、材质批次、中心净空、栖点、显现、地面承托，以及复原柱与方孔的对位数量。
- [九处地标取景](map-landmarks.jpg)来自相同地形函数上的近景资产核验场。[完整入口的试玩记录](../campaign/playthrough.json)由主游戏的流程测试生成。
- [三种野外旁注的物理实测](observation-reach.json)使用只读进度夹具解锁九站，从渡口干地开始，用正式移动、碰撞、停栖和辨迹模块连续行进 116.324 米。潜水观察时烁羽距伏木模型表面约 0.264 米，玉棚降落点与栖点重合，柱场辨迹时九根复原柱均已显现。水面停留、飞近玉棚、关闭辨迹飞过柱场的三个对照均保留未获得状态。

在开发服务运行时执行 `node scripts/verify-fieldwork-v10.cjs` 和 `node scripts/verify-stations-v10.cjs`。两个测试默认连接本机 5197 端口，也可以通过 `JINSHA_ORIGIN` 指定其他 Vite 地址。树桩地图模型可通过 `node scripts/build-fieldwork-root-lod-v10.mjs` 从现有工程资产重新生成。

旁注物理实测通过 `node scripts/verify-observation-reach-v10.mjs` 运行。它自行打开本机临时 Vite 服务，在无 GPU 渲染的无头浏览器中提交控制器级按键输入。报告中的时间是角色运动的模拟时间。
